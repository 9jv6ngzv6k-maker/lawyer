### 12. LCP на телефоне < 2,5 с — P1
Условия: 390×844, DPR 2, медленный 4G (RTT 150 мс, 1,6 Мбит/с вниз, 750 кбит/с вверх), CPU ×4, кэш выключен, **сервер с gzip** (как будет в продакшене). Медиана трёх прогонов. LCP-элемент — `p.lead` на первом экране.

Мои замеры v8:

| Условия | LCP |
|---|---|
| gzip | 4,48–4,56 с |
| без gzip (`python -m http.server`) | 3,04–3,26 с |
| gzip + reduced-motion | **1,52–1,75 с** |
| без gzip, шрифты и видео заблокированы | 2,75–2,88 с |

Главный тормоз — не шрифты, а **входная анимация первого экрана**: `.lead` появляется из `opacity: 0` с задержкой 640 мс после выполнения `app.js`. Шрифты тоже мешают: до `load` загружаются все 22 woff2 (~ 350 КБ).

Сделать:
1. **Шрифты** (замечание SEO). Сразу загружать и предзагружать только файлы, нужные первому экрану: кириллица Onest 400 и Playfair 400. Если без латинского набора на первом экране не отрисовываются цифры и знаки препинания, их тоже. Все остальные начертания (EB Garamond, JetBrains Mono, Onest 500–700, italic, латиница, не нужная первому экрану) грузить отложенно, после `load`. Шрифты локальные.
2. **LCP-элемент.** `.lead` и h1 видимы с первого кадра (`opacity: 1`). Входная анимация только через `transform` (сдвиг сохранить). Итоговый вид первого экрана не меняется.

Приёмка: медиана LCP < 2,5 с в условиях выше. До LCP запрошено ≤ 4 woff2. Итоговый вид первого экрана на 1440 и 390 совпадает с v8 (сравнение скриншотов через 3 с).
